# تطبيق تجارتي Android — Flutter

مشروع Flutter/Dart لتطبيق Android العربي RTL، مربوط بخادم الإنتاج:

```text
https://t3lam.site/s_api/api/v1
```

## ما أُنجز في الدفعة الأولى

- مشروع Flutter Android أصلي باسم الحزمة `com.tijarti.tijarti_mobile`.
- واجهة Material 3 عربية RTL مستوحاة من تصميم تجارتي على الويب.
- اتصال HTTPS فعلي بـ API الإنتاجي عبر Dio واستجابات API الموحدة.
- تبويب رئيسي: الرئيسية، المتاجر، الحراج، الحساب.
- تحميل متاجر وإعلانات الحراج الحقيقية من الخادم، مع حالات الفراغ والخطأ والتحديث.
- تسجيل دخول وتسجيل حساب عميل عبر API وحفظ رمز الدخول في `flutter_secure_storage` فقط.
- تصفح تفاصيل المتاجر والإعلانات ومنتجات المتجر، مع صورها وأسعارها وبياناتها العامة.
- سلة مشتريات حقيقية مقسمة بحسب المتجر: إضافة منتج، تعديل الكمية، حذف المنتج، وتحديث مباشر من الخادم.
- عناوين التوصيل: إضافة وتعديل وتعيين العنوان الافتراضي عبر API.
- Checkout آمن لكل متجر مع الدفع عند الاستلام أو التحويل اليدوي، بمفتاح idempotency لكل عملية.
- قائمة الطلبات وتفاصيلها وسجل الحالة، إلغاء الطلب في المراحل المسموحة، تأكيد الاستلام، ورفع سند تحويل خاص للدفعات اليدوية.
- SQLite عبر `sqflite` لكاش المحتوى المحلي وبنية queue للعمليات المؤجلة غير المالية.
- لا تحفظ رموز الدخول أو الطلبات أو الأرصدة أو الصلاحيات كمصدر حقيقة في SQLite؛ الخادم هو المرجع.
- صلاحية `INTERNET` لتطبيق Android.
- اختبارات نماذج البيانات الأساسية.

## تشغيل التطوير

يتطلب Flutter 3.47+ وJDK 17 أو أحدث وAndroid SDK.

```bash
cd mobile
flutter pub get
flutter analyze
flutter test
flutter run
```

## تغيير رابط API دون تعديل الكود

الرابط الافتراضي مضبوط للإنتاج. لتوجيه إصدار staging أو خادم جديد:

```bash
flutter run --dart-define=API_BASE_URL=https://example.com/s_api/api/v1
```

## المسار التالي

1. البحث والتصنيفات وصفحات المنتج المستقلة، ثم إنشاء إعلان الحراج والمفضلة والمراسلة والعروض.
2. مساحات التاجر وعامل التوصيل والإدارة حسب الدور.
3. مزامنة queue المحلي للعمليات غير المالية عند استعادة الاتصال.
4. إعداد `google-services.json` من Firebase لمعرف حزمة Android أعلاه ثم FCM حي على جهاز فعلي.
